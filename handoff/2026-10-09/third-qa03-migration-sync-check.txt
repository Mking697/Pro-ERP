1. Traced actual current content first (finding's line numbers were stale)
----------------------------------------------------------------------------
Original scripts/check-migration-sync.ts (before this fix) at the time of tracing:
  - Read drizzle/meta/_journal.json, took journal.entries.length as "localCount".
  - Queried `SELECT COUNT(*)::text AS count FROM drizzle.__drizzle_migrations` for
    "appliedCount".
  - Compared ONLY the two integers (appliedCount > localCount => "ahead" error;
    appliedCount < localCount => "behind" warning; equal => "In sync", unconditionally).
  - No hash, no timestamp, no per-entry comparison anywhere. Confirmed the finding is
    real: an edited-after-applied migration file, or a reordered local/remote journal,
    with the SAME total count, hits the `appliedCount === localCount` branch and prints
    "✅ In sync" — silently wrong.
  - This exact gap was already called out by a prior session's own handoff note
    (handoff/2026-10-09/second-schema-migration.txt:187-194): "check-migration-sync.ts
    only compares counts ... it has no awareness of ... drift".

Confirmed tests/local-isolated/migrate.cjs's already-proven-correct comparison
(line 21): `assert.deepEqual(rows.map(r => ({hash, when: Number(r.created_at)})),
migrations.map(m => ({hash: m.hash, when: m.folderMillis})))`, where `migrations` comes
from drizzle-orm/migrator's `readMigrationFiles()` (hash = sha256 of the .sql file
content, folderMillis = the journal entry's `when`). This is the exact algorithm
mirrored below — no new algorithm invented.

2. Confirmed DB-free unit testing is possible (no live DB needed)
----------------------------------------------------------------------------
The script's comparison logic was inline inside `main()`, mixed with the DB query and
dotenv/db-client import — not independently testable. Verified (by reading
node_modules/drizzle-orm/migrator.js) that `readMigrationFiles()` returns plain
`{hash, folderMillis, sql, bps}` objects from local files with zero DB I/O, and the live
side only needs `{hash, when}` pairs. So the comparison itself is pure data in/data out
and needs no DB connection to unit-test — extracted it into an exported pure function.

4. Fix implemented (scripts/check-migration-sync.ts)
----------------------------------------------------------------------------
- Added `readMigrationFiles` (drizzle-orm/migrator, the same function
  tests/local-isolated/migrate.cjs uses) to get the local lineage as
  `{hash, folderMillis}[]` instead of only journal `{idx, tag}`.
- Changed the live-DB query from `SELECT COUNT(*)` to
  `SELECT hash, created_at FROM drizzle.__drizzle_migrations ORDER BY created_at`,
  mapped to `{hash, when: Number(created_at)}[]` — ordered by created_at, exactly as
  migrate.cjs's live assertion does.
- Extracted and exported a pure function `diagnoseMigrationLineage(local, applied)`
  that walks the ordered overlap and returns one of:
    "ahead"   — applied.length > local.length (unchanged meaning/message from before)
    "drift"   — same algorithm as migrate.cjs's assert.deepEqual, generalized to the
                overlapping prefix only (so a legitimate "generated but not yet
                migrated" local-ahead state is NOT flagged as drift) — reports the
                first mismatching index plus both sides' hash/when for diagnosis
    "behind"  — applied.length < local.length AND the overlapping prefix matched
                (unchanged meaning/message from before)
    "in-sync" — full equality, ordered, hash-for-hash and timestamp-for-timestamp
- `main()` now branches on `diagnosis.status` instead of two bare integer comparisons;
  the new "drift" branch exits 1 with a message naming the mismatched index/tag and
  both recorded hash/when pairs, distinct from the existing "ahead"/"behind" messages.
- Guarded the script's self-invocation (`if (isMain) main().catch(...)`) using
  `fileURLToPath(import.meta.url) === resolve(process.argv[1])` so the module can be
  imported by the test file (and any future caller) without triggering the dotenv/
  db-client/live-query side effects of `main()` — this is what made the pure function
  independently testable without mocking the DB client at all.
