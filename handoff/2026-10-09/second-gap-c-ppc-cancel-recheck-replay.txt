# Second-phase gap C — PPC plan cancel/recheck durable replay

## Scope
Closed the deferred gap: `PATCH /api/ppc/plans/[planId]` cancel/recheck branches
called `cancelPlan(planId)` / `reallocatePlan(planId)` with no idempotency key —
no durable replay protection on retry. Wired both to the same
`getMutationKey` + `runIdempotentTenantMutation` + committed-result-200 pattern
already used by this route's start/complete branches.

## Files changed
- `src/app/api/ppc/plans/[planId]/route.ts` — cancel/recheck branches now call
  `cancelPlan(planId, guard.session.email, getMutationKey(request))` /
  `reallocatePlan(planId, guard.session.email, getMutationKey(request))`.
- `src/lib/inventory/plans.ts` — `cancelPlan`/`reallocatePlan` gained
  `(planId, actorId?, key?)` signatures. When `key !== undefined` they delegate
  to `runIdempotentTenantMutation` (operations `ppc.plan.cancel.v1` /
  `ppc.plan.recheck.v1`), calling themselves recursively without the key to do
  the real work inside that wrapper's own transaction — exactly mirroring
  `completePlan`'s existing pattern. `actorId` is validated (`PlanError` if
  missing) only on the keyed path; the no-key path is untouched, so every
  existing caller (e.g. `tests/stock-workflow.real.test.ts`'s
  `reallocatePlan(id)`) keeps compiling and behaving identically.
  Confirmed via code read: both functions already ran inside
  `runInTenantTransaction` internally before this change — this was **purely
  route-level keyed-replay wiring**, no transaction redesign, matching the
  task's hypothesis.
- New files (both DB-free, `setupFiles: []`, mirroring
  `tests/replay-recovery-api.unit.test.ts`'s pattern without editing it):
  - `tests/ppc-plan-cancel-recheck-replay.unit.test.ts`
  - `tests/ppc-plan-cancel-recheck-replay.unit.vitest.config.ts`
