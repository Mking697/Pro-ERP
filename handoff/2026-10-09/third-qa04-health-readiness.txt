PROBLEM (confirmed by reading the actual prior file)
Prior src/app/api/health/route.ts always returned HTTP 200 / status:"ok" and
derived `configured.database` purely from `Boolean(process.env.DATABASE_URL)`
— i.e. it reported "ready" based on an env var being SET, never on the
database actually being reachable. That conflates process liveness (the
Next.js handler is running) with readiness (the DB answers queries right now,
on the expected schema).

FIX
- Added `checkDatabaseReadiness()`: a bounded (2500ms) real connectivity
  check using the SAME client the app already uses, `db` from
  `@/db/client` (no second pool/config) — `select 1`, then a schema-version
  signal read from `drizzle.__drizzle_migrations` (same table/columns
  `scripts/check-migration-sync.ts` and `tests/local-isolated/migrate.cjs`
  already read): `SELECT hash, created_at FROM drizzle.__drizzle_migrations
  ORDER BY created_at DESC LIMIT 1`.
- `Promise.race` against a timeout promise bounds the whole check; a timeout
  or a thrown error both resolve to `{ reachable: false, error }`.
- GET response now has:
  - `status: "ok"` — liveness, unconditional (the handler ran)
  - `ready: boolean` — readiness, true only if the DB check succeeded
  - `database: { reachable, latencyMs, schemaVersion | error }`
  - `configured.database` — unchanged meaning: env var presence only
  - HTTP status is 200 when ready, 503 when not ready (DB unreachable,
    timed out, or DATABASE_URL absent)
- Liveness fields (`status`, `commit`, `branch`, `configured`) are reported
  regardless of DB readiness, so the two concerns stay genuinely separate
  in the one payload, as required.

TEST COVERAGE (4 cases, all passing GREEN)
- DB query rejects -> ready:false, database.reachable:false, HTTP != 200,
  liveness (status:"ok", configured.database:true) still reported.
- DB query never resolves -> bounded timeout fires, ready:false, HTTP != 200.
- DB query succeeds -> ready:true, HTTP 200, schemaVersion populated with the
  real hash/appliedAtMs read from the (mocked) __drizzle_migrations row.
- DATABASE_URL absent -> ready:false, HTTP != 200, and the DB client is never
  even called (h.execute not called) — no wasted query when clearly
  unconfigured.
