UX-01: board requests now carry AbortSignal and monotonically increasing IDs.
Tab switches, mutation refreshes and Retry synchronously invalidate the old request,
set pending=true and clear the old error before the effect fetch starts. Cleanup
invalidates/aborts requests on unmount or effect replacement. Late successes/errors
cannot replace current data or clear another request's pending state. Non-2xx JSON
and non-JSON responses are rejected with HTTP status. Errors are persistent alerts
with an explicit Retry button. Last-known-good results are preserved per tab, so a
failed Issued refresh cannot render Draft's cached rows under the Issued heading.
Existing board dialogs/input are not reset by transport errors. Dialog-internal
mutation error handling was not edited (outside ownership).

UX-02 choice: deliberately BLOCK session-switching/New Chat throughout a send.
Disabled controls plus a synchronous flight ref (session ID + optimistic message ID)
prevent switching/double-submit even before React's next render. History requests
remain switchable, but only the latest request ID can apply; New Chat invalidates
history and clears pending. Sending is blocked while history loads, preventing late
history from replacing optimistic bubbles/replies. Failed sends remove only their
optimistic ID, never slice(0,-1). Unmount suppresses late transcript updates. Failed
network send restores the draft. No backend, DB, schema or transport policy edits.
Abort cancels browser waiting; it is NOT claimed to cancel server-side work.
