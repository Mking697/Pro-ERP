- src/components/ui/label.tsx — NOT modified. Inspected first per instructions: `Label`

## What was wrong
Every repeated per-row field (Qty/Rate per order line, New Price per PO candidate row) and
several single fields used a bare `<Label>Text</Label>` with no `htmlFor`, paired with an
`<Input>`/`<Textarea>` with no `id` — the label and control were only visually adjacent
siblings, not programmatically associated. A screen reader announced "Quantity" with no
line context, and clicking the label text did nothing (didn't focus the input). No field had
`aria-invalid`/`aria-describedby`, so even the one validation message that did exist (a
generic toast) was invisible to assistive tech and not tied to any specific row.

## Fix — src/app/orders/new-order-dialog.tsx
- Per order line (keyed by the line's own stable `line.key`, never the array index, so a
  removed earlier line can't silently re-point another line's ids):
  - Qty: `id="order-line-qty-${line.key}"`, `Label htmlFor` matching.
  - Rate: `id="order-line-rate-${line.key}"`, `Label htmlFor` matching.
  - Added a `submitAttempted` state (set true on `handleSubmit`, reset on dialog
    close/reset) so a line with an item selected but `qty` not `> 0` now gets
    `aria-invalid="true"`, `aria-describedby` pointing at a new visible inline error
    `<p>` (`order-line-qty-error-${line.key}`), in addition to the existing toast.
  - Rate intentionally got only id+htmlFor, no aria-invalid — there is no actual rate
    validation in `handleSubmit`/the API today, and fabricating one wasn't in scope.
- Single fields also fixed for completeness (not repeated, but still unassociated before):
  GST % (`order-gst-percent`), Transport Arrangement (`order-transport-arrangement`,
  `SelectTrigger` now carries the `id` a `<label htmlFor>` can target — base-ui's Select
  trigger renders a real `<button>`, which is a labelable element).
- Left alone (out of ownership / already correct): the "Customer" label (wraps
  `CustomerPicker`, a sibling component not owned by this task), `ItemPicker`'s own
  per-instance `Label htmlFor={useId()}` (already correct, ships its own comment
  explaining the exact same repeated-row bug class), the per-row Checkbox/"PO
  Attachment" (`FileUploadField`) which already carry their own distinct
  `aria-label`/label wiring in components not owned here.

## Fix — src/app/purchase/po-issue-board.tsx
- Vendor select: `id="po-vendor"` on `SelectTrigger`, `Label htmlFor="po-vendor"`.
- GST % / Note / Terms & Conditions: `id`s `po-gst-percent` / `po-note` / `po-terms`,
  each paired with `Label htmlFor`.
- Per-candidate-row New Price input (the repeated-row case this file was cited for),
  keyed by `r.candidate.indentId` (the row's own real identity, not array index):
  - Added a stable `id="po-new-price-${indentId}"` (the row already had a correct,
    distinct `aria-label` giving each row its own accessible name — that part was
    already right; it just had no `id` and no validation wiring).
  - Added `aria-invalid`/`aria-describedby` wired to a new, row-scoped `sr-only`
    (`role="alert"`) error message when the typed price is non-empty and negative
    (`Number(priceValue) < 0`) — this previously had no inline validation at all; a
    visually-hidden message was used (not a visible one) to avoid disturbing this
    dense table's layout, following the existing `sr-only` convention already used
    elsewhere in this codebase (`command-palette.tsx`, `file-upload-field.tsx`,
    `loading-states.tsx`, `dialog.tsx`).
